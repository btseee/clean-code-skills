# Strapi

> Applies to: Strapi 5. Language pack: `javascript.md` or `typescript.md`. Read with: nothing.

## Structure

- `src/api/<name>/content-types/<name>/schema.json` — the content type's attributes; the single source of truth for its shape.
- `src/api/<name>/controllers/` — one file per content type, generated by `createCoreController`; thin by default.
- `src/api/<name>/services/` — one file per content type, generated by `createCoreService`; business rules and Document Service calls live here.
- `src/api/<name>/routes/` — generated by `createCoreRouter`; rarely hand-edited beyond a custom route's `config`.
- `src/api/<name>/policies/` — authorization checks that gate a route before its controller action runs.
- `src/api/<name>/middlewares/` — request/response processing scoped to this API.
- `config/middlewares.ts` (or `.js`) — registers global middleware and its order.
- `src/index.ts` — `register()`/`bootstrap()`; wires third-party clients and cross-cutting setup once at startup.

## Roles

```clean-roles
role controller = src/api/*/controllers/**
signal controller = createCoreController
role service = src/api/*/services/**
signal service = createCoreService
role route = src/api/*/routes/**
signal route = createCoreRouter
role policy = src/api/*/policies/**
role middleware = src/api/*/middlewares/**
role content-type = src/api/*/content-types/**
```

## Rules

- Put every Document Service call (`strapi.documents(uid)...`) in a service; a controller calls its own service, never `strapi.documents` directly (G17).
- Override only the action a request truly needs inside `createCoreController`'s callback; leave the rest to the generated default (small classes, Ch10).
- Keep a policy to one authorization decision; compute the business rule in a service and have the policy call it, not reimplement it (G14).
- Reserve lifecycle hooks (`content-types/*/lifecycles.*`) for bookkeeping on the record's own fields; put a request-triggered business rule in a service method instead, since Strapi 5 changed when and how often these hooks fire under the Document Service API.
- Validate a custom route's input the same way the generated routes do, before it reaches a service.
- Reuse another content type's logic through `strapi.service('api::other.other')`, never by importing its service module's internals directly.

## Layers

Applies only when `.clean/architecture.md` declares layers.

- The Document Service API (`strapi.documents`), the Koa `ctx`, and generated controllers/routes are delivery and persistence details; keep a business rule in a plain function a service calls, so it can be tested without `strapi` (the Dependency Rule).
- Declare a plain interface for any outbound call a service makes (email, payment, search index); implement it in a provider built in `register()`/`bootstrap()`, and inject it rather than importing the vendor SDK inside the service body.
- `src/index.ts` and `config/` are the composition root: third-party clients and cross-cutting wiring are built there, once.

```clean-architecture
layer application    = src/api/*/services/**
layer infrastructure = src/api/*/content-types/**
layer delivery       = src/api/*/controllers/**, src/api/*/policies/**, src/api/*/middlewares/**, src/api/*/routes/**
layer main           = src/index.*, config/**
```

## Tests

- Test a service's exported functions directly, with `strapi.documents` faked behind the interface it was called through.
- Test a policy by calling it with a constructed `ctx` (or `policyContext`) and asserting the authorization outcome.
- Reserve a real Strapi instance plus HTTP calls for the handful of routes whose policies and lifecycle interactions most need proving together.
- Assert a Document Service result through the same API the code under test used; never re-verify it with a raw database query.

## Enforce

- ESLint via `@strapi/eslint-config` (or the project's own config) plus the language pack's rules; `tsc --noEmit` in TypeScript projects.
- dependency-cruiser or `eslint-plugin-boundaries` forbidding one API's `controllers/**` or `content-types/**` from importing another API's `services/**` directly.
- `strapi generate` to scaffold a new controller, service, or content type, so generated files stay consistent with the factory pattern the framework expects.

## Smells

- A `content-types/*/lifecycles.*` file computing a business rule instead of touching only its own record's fields (G17).
- A controller calling `strapi.documents(...)` or `strapi.db.query(...)` directly instead of delegating to its service (G17).
- A policy that reaches into business rules or persistence to decide, instead of asking the service for a decision (G14).
- The same computation duplicated in a lifecycle hook and a service because no one owns it (G5).
- A custom controller action longer than the generated ones around it, with logic that belongs in a service (G30).
